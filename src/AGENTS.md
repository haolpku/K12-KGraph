# `src/` 源码规则

本文件适用于 `src/` 下的所有源码。项目级环境、凭据、文档和数据安全规则见上级 `../AGENTS.md`。

## 模块边界

- 检索后端放在 `src/retrieval/`。
- 知识图谱构建流水线放在 `src/kg/`。
- Benchmark 构建放在 `src/benchmark/`。
- SFT 数据构建放在 `src/sft_qa/`。
- 通用且确实被多个模块复用的代码放在 `src/utils/`；不得把检索专用逻辑提前抽象成通用工具。
- 后续前端代码放在 `src/frontend/`，不得放入 `src/retrieval/`。

## 依赖和运行环境

- 所有源码共享项目根目录由 `uv` 创建的 `.venv`。
- 不得在 `src/` 或其子目录创建 `.venv`、复制依赖包或提交生成环境。
- 模块间引用使用稳定的包导入，不通过动态修改当前工作目录建立隐式依赖。
- 新增依赖必须在项目根依赖文件中声明，并验证 Docker 和测试环境一致。

## 实现原则

- 优先复用现有模块、数据模型和错误契约，再考虑新增抽象。
- 公开接口与内部实现分离；Provider SDK、数据库驱动和外部模型调用应封装在 Adapter 或 Store 边界。
- 不在模块导入阶段执行数据写入、网络调用或不可逆操作。
- 错误必须保留可诊断的原因码，但不得包含凭据、完整提示词或敏感数据。
- 对外返回值使用明确的数据模型，不以无约束字典替代稳定契约，确属扩展属性的字段除外。

## 测试要求

- 源码行为变化必须增加或更新对应测试。
- 安全、权限、路由、数据泄露和错误回退必须包含负向测试。
- 测试不得依赖真实 API Key、生产 Neo4j 或用户现有持久化数据。
